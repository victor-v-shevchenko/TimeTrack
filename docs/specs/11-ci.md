# Step 11: CI pipeline

## Goal
Every push to `master` and every pull request is built and tested on GitHub Actions, so a reviewer
sees a green check instead of having to trust the README.

## Depends on
Steps 1–10.

## Files

    .github/workflows/ci.yml

## Jobs
1. **backend**: .NET 10 SDK, `dotnet restore/build/test backend` against a `postgres:17` service
   container. The tests create and drop their own databases, so they only need a server.
   The service uses `POSTGRES_HOST_AUTH_METHOD: trust` and the connection string has no password:
   the container lives only for the job, and no credential is committed (CLAUDE.md, Secrets).
2. **frontend**: Node 24 (the version in `frontend/Dockerfile`), `npm ci`, `npm test -- --watch=false`
   (Vitest), `npm run build`.
3. **images**: after both pass, `docker build` the API and web images exactly as Compose does.
   Images are built, not pushed.

Workflow permissions are read-only; a newer run on the same ref cancels the older one.

## Acceptance criteria
- [ ] The workflow runs on a pull request and all three jobs pass.
- [ ] A failing backend or frontend test fails the run.
- [ ] No credentials or connection strings with passwords in the workflow.
- [ ] README shows the CI badge, mentions CI under Tests, and "a CI pipeline" is removed from Possible improvements.
